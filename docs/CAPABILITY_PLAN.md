# 麦麦预算助手：按一顿饭组织 MCP 能力

更新：2026-10-13。依据官方 https://github.com/M-China/mcd-mcp-server 及实时工具定义，不将文档示例作为真实账号结果。

产品假设：用户希望按预算和口味选择一顿饭，并保留该搭配完成购买；是否能省钱、节省多少操作仍待真实使用验证。

| 顺序 | 用户任务 | MCP 能力 | 当前状态与验收 |
|---|---|---|---|
| 1 | 选好就继续买 | 菜单、详情、calculate-price、create-order、query-order | 自取与麦乐送确认页、完整核价已真实验证，创建和付款待用户实测。用户不必在官方入口重新搜索搭配；服务端订单子项需要核对 |
| 2 | 用我的券买得合适 | query-my-coupons、query-store-coupons、calculate-price | 目前只查门店券，没有自动应用。下一版针对能映射到真实餐品的适用券分别核价，显示用了哪张券、实际价差；无法匹配如实说明。领券另做明确点选的 auto-bind-coupons 入口 |
| 3 | 上次喜欢的再来一份 | order-list、query-order、cancel-order | 当前“最近订单”仅本机记录。下一版再接账户历史，读取实际餐品重新核价，禁止用历史金额下单；取消前展示订单状态并确认，不能承诺一定可取消 |
| 4 | 偏好更具体 | list-nutrition-foods、餐品 modification | 营养千卡已按实际选配、具体产品与数量接入，并真实验证换小食联动；不推算未知套餐。去冰、去酱等只展示官方详情支持的特制选项，完整写入核价和订单 |
| 5 | 不浪费积分快到期权益 | query-my-account、mall-points-products、mall-product-detail | 已接入只读可用积分和本月/下月到期查询。可兑商品仍待开发，不混入现金餐品价格。兑换另行确认积分、收货方式和商品，不自动扣积分 |
| 6 | 改用餐场景或预约活动 | 配送地址与门店、预约参数、派对城市/门店/日期/场次 | 已有即时到店和麦乐送配送，外送先选已有地址并按整单核价；新增地址在官方渠道操作，预约仍待开发；活动预约独立流程，避免占据日常搭配入口 |

积分抽奖与企业团餐暂放后面，除非真实用户有需求。将全部33个工具做成首页按钮不会自动带来价值。

先用3位真实用户做同一个任务：设定预算和偏好，选一份愿意买的搭配，走到真实官方支付页（是否付款由本人决定）。记录是否能直接继续、哪里需要重选、选择用时、为何放弃；至少隔天观察是否愿意再用。创建订单和取得支付链接，只证明系统交接成功，不能单独证明省钱或复用价值。
