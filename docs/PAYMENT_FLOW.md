# 官方支付与取餐进度（0.8.0）

2026-10-14 核对[麦当劳 MCP 文档](https://open.mcd.cn/mcp/doc)与实时 tools/list。create-order 的工具说明明确引导支付链接扫码或官方 App 完成支付，再查询订单状态。query-order 用 orderId 查询结果。工具列表未提供独立支付宝交易号、指定支付宝渠道或代付工具。

## 这版实现

选择搭配 → 再核价与确认门店/取餐方式或配送地址 → 本人明确创建订单 → 返回官方订单编号与支付链接 → 勾选核对 → 打开官方收银台或显示手机扫码二维码 → 付款后查询 query-order → 展示实际 pickupCode / lockerCode。

- 二维码只在本机编码麦当劳实际返回、已核对的 HTTPS 支付链接。生成前重新查询该账号的订单。不会发订单链接给第三方二维码服务，也不创建另一笔交易。
- 已支付、超预算、金额未知、截止已过、未知状态或不匹配支付地址不生成二维码。支付地址仅允许当前已确认的生产入口、当前订单编号，不接受附加跳转参数。
- 打开支付页或显示二维码后，每20秒查询一次，最多5分钟；隐藏页面暂停，返回页面立即查询。失败保留上次结果，自动查询暂停；手动查询仍可用。已取得取餐码、已进入配送或终态时停止自动查询。
- 待支付显示“应付金额”，不称为实付。订单编号、取餐码可以复制；柜密码仅有官方实际返回才显示。已支付但取餐码为空时明确等待，不截取订单编号制造取餐号。
- 官方文档包含中文 orderStatus，兼容明确的中文值及数字码；未知状态不推断支付成功。无时区支付截止按北京时间解释。
- 最近订单仍仅限该 MCP 账号在本机创建的记录，重新打开会查询最新状态。

## 支付宝接入结论

目前接入麦当劳官方收银台；支付宝是否可选需在这笔订单的真实收银台验证，不承诺可直接使用支付宝扫描此链接。

[支付宝网页/移动应用接入](https://open.alipay.com/module/webApp)需要创建应用、开发配置及审核；[支付宝官方多商家收款说明](https://github.com/AlipayDocs/open-docs/blob/main/support/支付宝小程序/案例分析/小程序支付如何实现多商家收款.md)说明了商家授权、商户交易创建及交易号的关联。项目目前没有麦当劳的支付宝商户授权或对应交易号。用开发者自己的支付宝收款接口生成订单，会成为另一笔收款，不能据此把麦当劳订单标记已支付。

若官方收银台不支持支付宝，需要麦当劳提供或确认对应渠道、商户授权及交易关联方案，再做直接接入。当前没有添加自有支付宝收款按钮，也没有伪造付款回调。
