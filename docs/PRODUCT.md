# 当前产品范围（0.7.0）

麦麦预算助手是手机优先网页 + 独立 WorkBuddy Skill。网页负责操作和方案比较，Node 后端负责真实 MCP 查询、套餐候选筛选、完整选配核价；共享规则文件约束两种入口。

## 用户流程

输入地点、预算和餐品偏好（或提取有限关键词）→ 查询附近门店 → 点击选择 → 查询菜单和优惠券 → 读取候选套餐详情 → 选定具体饮料 → 官方核价 → 按口味及省预算/换着吃目标比较最多三套 A/B/C 方案。

点选餐品托盘，在图形弹窗选择当前接口返回的子项并核价；固定部分明确说明不能替换。也保留展开全部选配的下拉入口。调整饮料后立即显示待核算，旧金额失效，重新核价后再显示金额。三方案与同款跨店金额以总价横向图表示，不拆分未知单项价格。“选这套”只表达用户选择，不创建订单。预算不足时展示有限候选的检查范围及预算调整入口。当前一人份、即时到店场景和麦乐送已有地址配送。选中后可进入独立确认页，重新核价、选择取餐方式；用户明确确认后创建待支付订单，付款在官方渠道完成。页面最近订单可恢复本机记录并查询状态。真实下单与支付尚待用户实测。

默认保留预算、主食、严格无糖和地点；口味、杯型、排序目标与关键词提取折叠在更多偏好，标题持续显示当前杯型和排序。结果先展示餐品卡片，再按需展开价格对比图。修改同一门店的条件时，保留上次方案与选中项为参考，明确原预算与原核价，禁用复制、选配和对比；可以恢复原条件或按新条件查询。更换门店/地点仍重新查询，不混用门店结果。

桌面导航放在左侧，手机使用可关闭的侧边抽屉。预算与口味工作台排在活动雷达前；雷达默认收起，首次展开才查询，收起不清除套餐选择。早餐/午饭/小食快捷偏好和杯型偏好可手动调整。杯型图示有明显尺寸差异及标记；口味名称匹配不保证实际辣度。

候选最多12个套餐、18次具体搭配核价。每套独立核算，以主食/小食差异去重；不靠换杯凑数量，也不宣称全店最优。门店券查询失败时明确失败，继续按无券参数核价，不误报没有券。

## 两种入口

网页：本地 Node 服务 + 浏览器，电脑与手机布局自适应。查询使用用户本地配置，仅提供真实数据；未连接或查询失败显示原因，不以示例补位。

WorkBuddy：直接导入打包后的 Skill，或在工作目录读取 SKILL.md。读取 shared/policy.json，并用 scripts/check_plan.py 校验规范化计划；允许客户端 AI 更灵活地理解需求。网页的规则解析不能被描述成 LLM。

## 可扩展方向

已有券现在按门店与商品编码匹配并实际核价；后续再考虑单品组合搜索、多用户独立认证及公网部署。先用同一个套餐详情模型完成本版本，避免前端和 Skill 各自猜测数据字段。


## 场景与营养

外送先从用户账号读取已有地址，再查可配送门店。服务端重查地址和业务编码，不接受客户端猜测的beCode。预算限制用整单price，包含配送等费用；需要餐具时从核价起就携带参数，修改后旧报价不能继续下单。确认页增加脱敏联系人、真实地址、配送备注；外送不要求自取方式。

热量以官方energyKcal为准，保留杯型、份数和冷热，逐个实际选配匹配。完整时显示整餐参考千卡，不完整时显示已确认部分与未知项；不使用相似名称猜新品，不将标准热量应用到未知特制。积分到期面板按需查询，默认折叠，不干扰搭配。
