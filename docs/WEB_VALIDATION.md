# 网页验证与局限

网页版本 0.2.0，开发日期 2026-10-12。

## 数据路径

- 演示路径：合成套餐和选配，用历史试用金额启发交互数据；明确标为模拟结果，不宣称真实查询。
- 真实路径：后端从本地环境读取 Token，使用官方 MCP SDK，实时发现工具并通过 JSON schema 校验输入；只允许查询和算价。
- Node 后端已使用用户既有 WorkBuddy 本地 MCP 配置完成真实门店查询、套餐选配核价和饮料修改后重算。23元大杯无糖可乐配置改为中杯后返回21元；证据见 examples/web-live-2026-10-12.json。当前响应未回显饮料，不证明最终订单选配。

## 已知功能边界

- 单人、单门店、当前到店自取，最多8个套餐候选，返回最多2套预算内方案。
- 不穷举单品组合，不能声称全店最便宜或全店无解。
- 优惠券只查询、不自动应用；券接口异常时中止推荐，不能显示无券。
- 自然语言框仅提取有限关键词，不使用 LLM；用户须核对表单条件。
- 真实套餐详情必须具有已观察到的 rounds/choices 结构，未知结构停止候选，不猜测选配。
- 严格无糖只接受名称明确无糖/零糖标注，不根据普通茶或咖啡名称保证无糖。
- 服务器返回的价格未回显饮料时明确说明，不能确认最终订单。
- 修改后的方案处于待核算时不能复制成已报价方案；超预算也不能作为预算内方案复制。
- 本地服务仅监听127.0.0.1，拒绝其他 Host 和跨站 Origin。手机真机远程接入需单独配置受控访问。

## 试用前

使用自己的 Token 在 .env 中配置，重启服务，选择真实查询。逐步验证门店选择、菜单、详情、算价和修改选配。不要提交 .env 或原始认证日志。

## 自动化与浏览器结果

12项 Node 测试、6项 Python 测试通过，Skill格式验证通过。浏览器演示检查完成选店、生成、换饮料后的待核算与复制禁用、重算、低预算无方案、真实模式未配置提示。390px视口无横向溢出，可访问性检查检出0项违规（另有需要人工判断项）。

## 0.2.1 连接恢复修复

2026-10-12 复查发现原本地预览服务已停止，页面仍保留但 fetch 无法连接。新增服务离线横幅、重新检查按钮、可见页面的定期状态检查、请求超时及非 JSON 响应处理。认证、业务及网络错误使用不同错误码；全部候选因接口失败时不能显示预算无解。

增加启动脚本与 macOS 双击入口；重复启动检测同一应用已运行，避免端口冲突。通过独立 4313 测试服务执行“停服务→查询失败→离线提示→重新启动→点击重连→查询恢复”。真实 4310 服务也已复测门店与推荐。

修复后17项Node测试、6项Python测试通过。当前用户试用服务以独立进程运行；重启电脑后仍需要重新启动本地应用，不是公网托管服务。

## 0.2.2 预算可视化与移动端体验

缩短首页介绍区，加入预算占用进度、预算余量、两方案金额比较。比较仅使用当前两份已核算且预算内的金额，不能据此判断全店最低价；余量也不等于优惠。手机生成方案后收起条件，提供展开条件和调整条件入口，餐品卡片改为完整宽度。

修改选配后立即更新搭配清单，同时隐藏旧金额对应的进度和价差，并停止展示旧核算依据；重新核算成功后再更新。浏览器以演示数据验证鸡排堡方案从2280分改选红茶后变成2440分，预算占用从76%变成81%，与2500分方案的价差从220分变成60分。红茶演示仅在关闭严格无糖条件后进行，未把未知糖含量标为无糖。

22项Node测试通过，新增5项覆盖待核算、超预算、同价、反向排序及未知金额。390px视口无横向溢出，手机条件展开后仍可修改预算和重新生成；检查了修改选配前后的复制限制。可访问性自动检查未发现违规，仍有需要人工判断的项目。此次界面验收使用演示路径；真实接口的既有验证见上文，不将演示核价当成当前门店报价。
