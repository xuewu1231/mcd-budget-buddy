# 门店距离与已有券（0.9.0）

按用户这次选择完成“距离可视化 + 一键高德定位”，不让地图Key成为使用门槛。尚未启用内嵌地图，配置入口与门店位置数据接口保留。

## 从用户角度解决什么

| 真实决策 | 本版帮助 | 尚不能证明 |
|---|---|---|
| 去哪家吃 | 官方距离图与列表编号联动，一键到高德核对门店位置 | 距离是相对搜索地点，不能当作当前位置或步行路线；不估算步行分钟 |
| 现有券是否用得上 | 区分卡包资产、当前门店可用、当前套餐匹配，再实际核价 | 门店可用不保证每一套餐适用；不领券、不穷举多券组合 |
| 用券是否更划算 | 同选配无券/用券分别核价，整单更低才选择，并展示两次报价 | 差额不是对全部discount的归因；不承诺全店最低价 |
| 最后价格会不会变 | 选配、用券开关、门店变化后旧报价不可直接下单；确认前重新查券和核价 | 新品缺失选配、失效券或未知返回结构会阻止该券使用 |

产品现在可减少用户反复试券和重新搭配的步骤，但还没有真实多人使用测试证明节省多少时间、是否会复用。下一步可让3人各完成一顿真实想买的餐品，记录从选店到确认用时、改搭配次数和放弃原因；不要把增加MCP按钮数量当作价值证明。

## 核对事实与实现

2026-10-14读取实时tools/list：query-my-coupons为卡包资产，不校验当前门店/渠道；query-store-coupons为门店及订单类型可用券；calculate-price与create-order的items支持couponId、couponCode。实际大钟寺5家门店latitude/longitude均为0，本版不填坐标、不造地图落点。当前卡包totalCount=0，四道口门店返回0张券；无券路径真实可用，有效券折扣尚需账号持有适用券后实测。

- 用券开关可关闭，只处理已有券。最多18次价格计算；匹配到券时每份套餐占用两次计算，只试算一张匹配券。券专属套餐可进入候选，单品券不冒充套餐选配。
- API重新查询券，用不透明引用匹配当前门店及餐品；客户端不能指定任意券编码。报价、确认页与创建参数保持完整roundList和券参数。
- 失效、字段缺失、核价失败、同价或更贵时不给虚构优惠；失效的已选券在确认阶段要求重新核价，不静默去券。
- 地图入口使用[高德官方URI搜索](https://developer.amap.com/api/uri-api/guide/search/search)，只传公开门店名、城市与搜索展示选项。无真实坐标时继续展示距离图。
- 当前没有调用领取、取消、兑换、真实创建订单或支付来做开发测试。真实购买此前由用户反馈跑通，不能替代本轮有券消费验证。
